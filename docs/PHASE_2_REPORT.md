# المرحلة الثانية — المخزون المحلي

التاريخ: 2026-10-20. الإصدار: 0.2.0+2. نُفّذت المرحلة الثانية فقط بعد النسخة التأسيسية.

## ما أصبح يعمل

- SQLite فعلي على الجهاز، وترقيات schema من v1 إلى v2 دون حذف الجداول.
- جدول تصنيفات بمعرّفات ثابتة، ودفعات طعام مستقلة وسجل تغييرات.
- كل دفعة لها UUID وتاريخها المؤكد؛ الباركود قابل للتكرار عمدًا.
- الإضافة والتعديل والحذف مع التأكيد، وتكرار المنتج مع ضرورة اختيار تاريخ جديد.
- الاسم والعلامة والباركود والتصنيف والكمية والوحدة ونوع التاريخ والتخزين وتاريخ الشراء والسعر والصورة الاختيارية.
- الكمية تقبل الأرقام العربية والفارسية والفاصلة العشرية؛ القيم غير المنتهية والسالبة غير المقبولة تُرفض.
- الاستخدام والتخلّص من الدفعة كاملة مع سبب اختياري، والعودة إلى المخزون بعد تنبيه مراجعة التاريخ.
- البحث والتصفية حسب التصنيف والمكان والحالة، والترتيب حسب التاريخ أو الاسم أو الإضافة.
- عرض بطاقات أو قائمة، وشاشة تفاصيل مرتبطة بنفس البيانات.
- الرئيسية تعرض أعداد المنتجات الفعلية، بما فيها القريبة والمتجاوزة والمستخدمة، وتتحدث بعد التغييرات.
- «استخدمها أولًا» يستبعد المنتجات ذات التواريخ السابقة والمستخدمة أو المتخلّص منها.
- حساب الأيام حسب التقويم المحلي، مع تحديث بعد منتصف الليل وعند عودة التطبيق.
- دعم العربية والإنجليزية والثيمين والنص المكبّر، وصيغ جمع صحيحة للعدد.

## سلامة البيانات

تعديل الطعام وكتابة الحدث يتمان في معاملة واحدة؛ إذا فشل الحدث تُلغى عملية الطعام.
تمنع revision الكتابة فوق نسخة تغيّرت أو حُذفت، ولا يغيّر التعديل تاريخ إنشاء الدفعة.
تحتفظ الأخطاء بآخر بيانات محفوظة؛ فشل القراءة بعد نجاح الكتابة يظهر كخطأ قراءة قابل للمحاولة
بدل دعوة المستخدم إلى إضافة الدفعة مرتين. لا توجد بيانات طعام تجريبية مزروعة في التطبيق.

تُنسخ الصور إلى مجلد مستندات التطبيق قبل ربطها بسجل. تُنظّف النسخ المؤقتة للنموذج عند إلغائه.
الصور المحفوظة قد تشترك فيها دفعات مكررة؛ لذلك لا تُحذف عشوائيًا عند حذف دفعة.
تبقى أحداث الدفعة المحذوفة بلقطة بيانات محلية كما توضّح رسالة التأكيد. إدارة حذف كل البيانات
وتنظيف الصور غير المرتبطة مؤجلتان إلى إعدادات الخصوصية في المرحلة الخامسة.

## التحقق

- `flutter analyze --no-pub`: نجح دون ملاحظات.
- اختبارات Flutter: 37 اختبارًا للمنطق وSQLite والترقيات والواجهات والمقارنة البصرية.
- اختبارات Android: 3 اختبارات ناجحة على المحاكي API 34، تشمل:
  - نسخ صورة محلية من الملف المؤقت إلى المستندات والتحقق من بقائها بعد إزالة المصدر.
  - إضافة وتعديل واستخدام وتخلّص واستعادة وحذف دفعة عبر الواجهة مع SQLite الأصلي.
  - إغلاق قاعدة الاختبار وإعادة فتحها وبقاء التعديل، واحتفاظ الحذف بأحداثه المنفصلة.
  - الرجوع والتنقل واللغة والمظهر وحفظ التفضيلات عبر إعادة إنشاء التطبيق.
- اختبارات واجهة النموذج باللغتين تستخدم SQLite فعليًا عبر FFI؛ اختبارات الأخطاء تستخدم doubles مخصصة للاختبار.
- جرى اختبار العربية بحجم 150% وعرض 320، مع تحقق إضافي من قابلية تمرير نموذج الطعام.
- فُحصت صور الرئيسية بالعربية والإنجليزية في المظهرين. بيانات صور Golden اختبارات فقط.
- نجح بناء Android. الحزمة المخصصة للمراجعة: `artifacts/FreshKeep-phase2-debug.apk`، بنقطة تشغيل التطبيق العادية.

ملفات السجل المحلية: `phase2-tests.log` و`phase2-android-tests.log` و`phase2-final-build.log`.
هذه نتائج محاكي واختبارات آلية ومراجعة بصرية؛ لم يُجرَ اختبار TalkBack يدوي أو تجربة هاتف فعلي أو نشر Google Play.

## ما بقي

المرحلة الثالثة: مسح الباركود، مصدر معلومات المنتجات والتخزين المؤقت، OCR محلي وتحليل التواريخ وتأكيدها.
التذكيرات والوصفات والمشتريات في المرحلة الرابعة، والإحصائيات والإعدادات الموسعة في الخامسة،
والربح والاشتراكات والاستعداد للنشر في السادسة. لم تُفعّل إعلانات أو مشتريات أو خدمات مدفوعة.

حدّ التنبيه الحالي 7 أيام؛ تخصيصه سيأتي مع الإعدادات. عدّاد الاستخدام في الرئيسية مشتق من
سجلات الدفعات المحتفَظ بها، وليس تقريرًا تاريخيًا ماليًا أو ادعاءً بمبلغ تم توفيره.
